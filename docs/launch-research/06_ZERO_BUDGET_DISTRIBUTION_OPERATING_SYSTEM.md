# TabShow Zero-Budget Distribution Operating System

## Goal

Build distribution without paid ads by turning user pain into a repeatable content, community, SEO, and review loop.

Core idea:

> Find the tab without switching.

## The Loop

Every week:

1. Find pain.
2. Ship or highlight a small improvement.
3. Record proof.
4. Publish in one or two channels.
5. Convert useful discussion into website/Chrome Web Store copy.
6. Ask qualified users for reviews.
7. Track what moved.

## Weekly Tasks

### 1. Pain Signal Scan

Sources:

- Reddit: r/chrome_extensions, r/browsers, r/productivity, r/SideProject.
- Hacker News threads about browsers, Chrome, tabs, productivity, extensions.
- Product Hunt launches in productivity/browser tools.
- Chrome Web Store reviews for competitors.
- Search result snippets for tab manager alternatives.
- TabShow Featurebase: https://narsheek.featurebase.app/

What to capture:

- Exact phrases users use.
- Complaints about competitors.
- Screenshots or stories of tab overload.
- Trust/privacy objections.
- Feature requests repeated by multiple users.

Output:

- One weekly "pain language" note.
- One copy angle to test.

### 2. Small Improvement or Proof

Examples:

- Search shipped.
- Keyboard navigation shipped.
- Multi-window grouping shipped.
- Tab Chaos Score shipped.
- Hover delay improved.
- Works with 200+ tabs benchmark.
- Privacy/no-host-permissions explained.
- User-requested Featurebase item shipped.

Rule:

If nothing shipped, show proof or explain a design decision.

### 3. Demo Asset

Create one short video/GIF:

- 5-15 seconds.
- Shows too many tabs.
- Opens TabShow.
- Hovers through tabs.
- Snaps back.
- Clicks correct tab.

Reuse it across:

- Chrome Web Store.
- tab.show homepage.
- X/LinkedIn.
- Reddit post.
- Product Hunt gallery.

### 4. Publish

Rotate channels:

- Week 1: Reddit builder feedback post.
- Week 2: X/LinkedIn build-in-public post.
- Week 3: SEO/comparison page.
- Week 4: Product Hunt or Show HN-style launch/update.

Do not spam every channel with the same message at once.

### 5. Review Ask

Ask for reviews only after real usage:

- 5 panel opens.
- 20 previews.
- 3 tab switches.

Suggested copy:

"If TabShow helped you find a tab faster, a Chrome Web Store review helps other tab hoarders discover it."

### 6. Track

Track weekly:

- Chrome Web Store users.
- Review count.
- Rating.
- Website clicks to Chrome Web Store.
- Top traffic pages.
- Reddit/X replies.
- Most repeated objection.
- Most repeated feature request.

## Distribution Moat

The moat is not one launch. It is repeated public proof:

- People see the same clear phrase.
- They see the same visual aha.
- They see fast iteration.
- They see real user-requested features ship.
- They see honest competitor comparisons.
- They see privacy handled seriously.

That is harder to copy than a feature.

## Featurebase Role

Featurebase should be the public feedback and roadmap surface:

https://narsheek.featurebase.app/

Use it for:

- Collecting feature requests.
- Letting users vote on pain.
- Showing that TabShow is actively improving.
- Crediting user-requested features in changelogs.
- Creating distribution moments when requests ship.

Operating rule:

When a Featurebase request ships, publish a small changelog:

> Shipped from user feedback: [feature]. The goal is still the same: find the tab without switching.
